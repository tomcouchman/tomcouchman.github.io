TILDE_

An Android Wi-Fi companion designed to make connection-security signals clearer and easier to act on. I led the concept, product direction, testing and release, with AI-assisted software implementation.

Project 002 / Android & Networking

Security, without the noise.

Most people connect to unfamiliar Wi-Fi without much context about the network they have joined. TILDE_ is my attempt to translate useful connection information into plain language instead of presenting a wall of jargon or treating every unknown network as an emergency.

The project became a published Android app with connection awareness, Guardian monitoring, trusted-network profiles, VPN context, Connection Health and local history.

My role and development approach

I conceived TILDE_, set its feature and security goals, directed the user experience, tested Android builds, reported issues and guided revisions through to Google Play. I used AI coding tools for the Flutter/Dart and Kotlin implementation rather than writing that code myself.

Product design / Features

What the app does.

01 / AWARENESS

Connection context

Surfaces information about the current Wi-Fi connection and its reported security configuration in language non-specialists can understand.

02 / MONITORING

Guardian & alerts

Watches supported connection-state changes and surfaces useful notices rather than expecting users to constantly check a dashboard.

03 / TRUST

Trusted networks & Travel Mode

Lets users manage familiar network contexts and approach temporary or unfamiliar connections more deliberately.

04 / SUPPORT

Connection Rescue

Offers guided connection-health checks and practical troubleshooting explanations for everyday Wi-Fi problems.

05 / VPN

VPN awareness

Uses Android-reported VPN state to make the current connection easier to understand. It does not provide or replace a VPN.

06 / HISTORY

Local history & widgets

Helps users review important network events, with quick home-screen status and optional TILDE_+ capabilities.

My contribution / Delivery

How I took the idea to release.

Technology used: Flutter/Dart for the interface and Kotlin for Android features and widgets. The implementation was AI-assisted; I am not presenting those languages as my personal coding skills.

01 / PRODUCT DIRECTION

Concept and requirements

I defined the app’s purpose, requested its features and prioritised clear, useful explanations of Wi-Fi security rather than dramatic warnings.

02 / AI-ASSISTED BUILD

Guiding implementation

I used AI coding assistance to produce and revise the Flutter/Dart and Kotlin code, describing desired behaviour, reviewing results and requesting changes when something did not work.

03 / HANDS-ON QA

Testing and feedback

I tested Android builds, identified interface and feature issues, reviewed accessibility and large-text behaviour, and checked fixes during successive iterations.

04 / DELIVERY

Publishing and learning

I worked through release preparation and Google Play testing, and learned to evaluate security claims, limitations and user-facing guidance.

Honest security boundaries matter.

Wi-Fi encryption details, VPN status and connection signals are clues—not proof a network is trustworthy or that a device is safe. TILDE_ is a companion for awareness and guidance; it is not antivirus software, a firewall, a VPN or a guarantee against malicious networks. Designing around that distinction has been an important part of the project.

Reflection / Relevance

Why it belongs in a security portfolio.

Network fundamentals

Applying Wi-Fi security concepts, trust, VPN context and change monitoring to a real user-facing product has helped reinforce theory.

Defensive mindset

Good security communication depends on evidence, clear limitations, prioritisation and helping people make informed decisions.
